**调研结论（关键，长期有效）**：米家设备详情页 = **RN 插件化**，不是 spec 平铺：

- **无法 100% 复刻**：插件是 Android 平台 RN bundle，鸿蒙 ArkTS 无法加载（需 RN 运行时 + 米家插件 SDK）。第三方只能做 spec 卡片兜底。

**重构 DeviceControl.ets 为卡片式布局**（对齐米家 spec 卡片结构）：
- 顶部卡：大 emoji 图标(52px) + 设备名 + 在线状态点
- 状态卡：只读数值属性 → 2列 Grid 大数字（温度24.6°C/湿度61%/电量94%）
- 控制卡：可写属性 → 开关行/滑块列（去掉每项独立卡片，改为卡内项）

关键教训：**米家详情页是 RN 插件（fetch_plugin 返回 zip），第三方无法复用，只能用 spec 卡片对齐"结构"而非"像素"**；**fetch_plugin 响应 result.latest_info[].download_url 是插件包地址，sdk_version/platform 标识平台**。

## RN 复用米家插件的最终结论（09:30，决定性）
用户说"开整"，搭环境前先深挖 bundle 入口，发现**决定性证据**，结论收敛为"走不通"：

1. 米家插件 bundle 是**插件包，不是独立应用**：
   - 末尾入口是 `__r(10120); __r(10001);`，**没有 `AppRegistry.registerComponent` / `runApplication`**
   - 模块 10120 = `initializeCore`（require 老架构核心模块 + GlobalPerformanceLogger）
   - 模块 10001 = `exports.setConfig` + `init(targetConfig)`（异步 `_initPackage.init`）
2. **bundle 自带 RN 0.60 老架构运行时**：`BatchedBridge` 出现 13 次，initializeCore require 的是老架构核心（BatchedBridge/MessageQueue），与 RNOH 新架构（Fabric+TurboModule，无 BatchedBridge）是**两套运行时**，直接加载必然在核心层冲突。
3. 61-interop 是**源码级**兼容（需 index.js 源码重新打包），米家只有二进制 bundle，救不了。
4. MIOT 直接方法调用极少（MIOTService.currentDarkMode×3 / MIOTPackage.apiReport×2 / MIOTHost.language×2），说明插件宿主协议是通过「先取 NativeModules 对象再调用」方式，但核心冲突在 RN 运行时层，不在业务 stub 层。

环境勘察：Node 22.22.2 / npm 10.9.7 ✅，npm registry 可达，DevEco Studio + HarmonyOS SDK 6.0.2(API 22) + hdc 齐全 ✅（满足 RNOH API≥17 要求）。

**最终结论（不再摇摆）**：RN 复用米家官方插件 UI 在架构层走不通（二进制插件包自带 RN0.60 老运行时 vs RNOH 新架构）。唯一能"接近米家观感"的可行路径 = **ArkTS 手工定制卡片**（复刻色温环/档位盘等，控制接已实现的 miot-spec）。

关键教训：**米家插件 bundle 是自带 RN 0.60 运行时的插件包（init(config) 入口，非 AppRegistry.runApplication），与 RNOH 新架构运行时冲突，这是架构层死结，不是 stub 能解决**；**搭 RNOH 环境前先静态分析 bundle 入口，可避免浪费半天搭环境**。

用户截图反馈：Path 绘制的电源符号/Tab 房子/人形/下拉箭头渲染出"又小又残"（电源只剩短竖线、Tab 图标几乎看不见）。**ArkUI Path 组件对 SVG A（弧线）命令渲染不可靠，且 commands 坐标不随组件尺寸缩放**。

最终方案（100% 可控）：手写 4 个 SVG 资源文件放 media/（ic_power.svg 电源弧+竖线 / ic_home.svg 房子 / ic_person.svg 人形 / ic_chevron_down.svg 下拉箭头），统一 24x24 viewBox、stroke 2 圆角、stroke 固定黑色；代码用 `Image($r('app.media.ic_xxx')).fillColor(动态色)` 显示——**鸿蒙 Image 对 SVG 源支持 fillColor 动态着色**（单色 SVG 标准做法），选中/开关状态换色只需改 fillColor。

关键教训：**ArkUI Path 的 A 弧线命令渲染不可靠，图标一律用 SVG 资源文件 + Image.fillColor**；**SVG 单色图标 + fillColor 是鸿蒙动态变色图标的标准方案**；**资源文件名必须小写+下划线**。
